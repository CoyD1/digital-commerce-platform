# Digital Commerce Platform

Учебный backend для продажи цифровых товаров и управления правами доступа к покупкам. Проект развивается поэтапно: от работы с базой данных до заказов, платежей и выдачи доступа.

Сейчас реализованы конфигурация приложения, подключение к PostgreSQL, миграции, модель и репозиторий пользователей, интеграционные тесты и проверки состояния API. Каталог, авторизация, заказы и платежи пока не реализованы.

## Стек

- Python 3.13+, FastAPI, Uvicorn
- PostgreSQL 16, SQLAlchemy 2.x, Psycopg
- Alembic, Pydantic Settings
- pytest, pytest-asyncio
- uv, Docker Compose

## Требования

Установите Python 3.13, uv и Docker Desktop. Перед запуском PostgreSQL откройте Docker Desktop и дождитесь готовности Docker Engine.

Команды ниже предназначены для Windows CMD и выполняются из корня репозитория. В PowerShell переменные окружения задаются другим синтаксисом.

## Первоначальная настройка

Установите зависимости из `uv.lock`:

```bat
uv sync --locked
```

Если файла `.env` ещё нет, скопируйте пример:

```bat
copy .env.example .env
```

Укажите в `.env` локальные параметры PostgreSQL. Для запуска приложения на компьютере используются `POSTGRES_HOST=localhost` и `POSTGRES_PORT=5433`. Имя рабочей базы — `commerce`. Пароль из примера замените своим. Файл `.env` не нужно коммитить.

Приложение читает `.env` автоматически через Pydantic Settings. Вводить `.env` как команду в терминале не требуется.

## PostgreSQL и миграции

Запустите базу в фоне и проверьте контейнер:

```bat
docker compose up -d postgres
docker compose ps
docker exec commerce_postgres pg_isready -U postgres -d commerce
```

PostgreSQL доступен на `localhost:5433`; внутри контейнера он использует порт `5432`. Данные сохраняются в Docker volume между перезапусками контейнера.

Перед миграциями проверьте `sqlalchemy.url` в `alembic.ini`: адрес и учётные данные должны соответствовать рабочей базе. Сейчас конфигурация Alembic задаётся отдельно от `.env`.

```bat
uv run alembic -c alembic.ini upgrade head
```

Команда применяет недостающие миграции до последней версии. На новой базе создаёт схему с нуля.

Проверить текущую версию и таблицы:

```bat
uv run alembic -c alembic.ini current
docker exec commerce_postgres psql -U postgres -d commerce -c "\dt"
```

Параметр `-U postgres` в примерах предполагает локального пользователя `postgres`. Если вы выбрали другого пользователя, замените его в командах.

Изменение модели SQLAlchemy не обновляет существующую базу автоматически: изменения схемы доставляются миграциями Alembic.

## Запуск API

```bat
uv run uvicorn app.main:app --reload --port 8001
```

`--reload` включает перезапуск при изменении кода для локальной разработки. Терминал остаётся занят сервером; остановка — `Ctrl+C`.

| Адрес                              | Назначение                                         | Ожидаемый ответ                |
| ---------------------------------- | -------------------------------------------------- | ------------------------------ |
| http://127.0.0.1:8001/docs         | Swagger UI                                         | Интерактивная документация API |
| http://127.0.0.1:8001/health       | Проверка ответа приложения                         | `{"status":"ok"}`              |
| http://127.0.0.1:8001/health/ready | Проверка подключения к PostgreSQL через `SELECT 1` | `{"status":"ready"}`           |

Readiness проверяет соединение с базой, но не наличие всех таблиц и актуальность миграций.

## Тесты

Тесты используют отдельную базу `commerce_test` в том же PostgreSQL-контейнере. Создайте её один раз:

```bat
docker exec commerce_postgres psql -U postgres -d postgres -c "CREATE DATABASE commerce_test;"
```

Если база уже существует, создавать её повторно не нужно.

В окне CMD задайте адрес тестовой базы и запустите тесты:

```bat
set TEST_DATABASE_URL=postgresql+psycopg://postgres:YOUR_PASSWORD@localhost:5433/commerce_test
uv run pytest -q
```

Замените `YOUR_PASSWORD` своим локальным паролем. Спецсимволы в логине и пароле должны быть закодированы для URL. Переменная, заданная через `set`, действует только в текущем окне CMD и запускаемых из него процессах; в новом окне задайте её снова.

Перед тестами session fixture автоматически применяет миграции. Она загружает `alembic-test.ini`, но подменяет URL значением `TEST_DATABASE_URL`, чтобы миграции и тестовые сессии работали с одной базой. Базу данных fixture не создаёт.

Запуск останавливается, если URL отсутствует или имя базы отличается от `commerce_test`. Каждый тест с `db_session` выполняется внутри транзакции, которая откатывается после теста. Схема при этом сохраняется. Ручная настройка `PYTHONPATH` не требуется.

При ручном запуске Alembic для тестовой базы URL берётся из `alembic-test.ini`, поэтому сначала проверьте его соответствие тестовому окружению:

```bat
uv run alembic -c alembic-test.ini current
```

## Структура

```text
app/
  api/          # Маршруты API и health checks
  core/         # Настройки приложения
  db/           # SQLAlchemy Base, engine и сессии
  users/        # Модель и репозиторий пользователей
alembic/        # Окружение и версии миграций
tests/          # Подготовка базы и интеграционные тесты
compose.yaml    # Локальный PostgreSQL
```
